# GSTR-3B API

GSTR-3B is a monthly or quarterly GST summary return used to declare tax liability and pay GST for a tax period on the GST portal. Use this API to fetch GSTR-3B details, auto-calculate liability, save return data, offset liability using cash and ITC, and file GSTR-3B with EVC OTP authorization.

## Compliance value

GSTR-3B filing is mandatory for all regular GST-registered taxpayers. This API automates the complete GSTR-3B workflow - from fetching portal data to filing with authorized signatory verification - following GST compliance requirements for Form GSTR-3B.

## Common use cases

Use GSTR-3B API when you need to:

- Automate GSTR-3B filing from ERP or accounting software for a GSTIN across periods
- Build an Application Service Provider (ASP) compliance workflow (save -> validate -> pay/offset -> file) for multiple client GSTINs
- Create a filing dashboard that tracks GSTR-3B processing using return status polling
- Reduce manual errors by validating portal responses after save and offset before filing
- Support nil filing for inactive GSTINs using the [File Nil GSTR-3B](/recipes/gst/gstr-3b/file_nil_gstr_3b) recipe

## FAQs

<AccordionGroup>
  <Accordion title="What is GSTR-3B and who needs to file it?">
    GSTR-3B is a monthly or quarterly self-declaration summary return for GST-registered taxpayers in India. All regular taxpayers must file GSTR-3B to declare their tax liability, claim Input Tax Credit (ITC), and pay GST for each return period. GSTR-3B consolidates sales, purchases, and tax liability data into a single submission. See the [GST API overview](/api-reference/gst/overview) for terminology and authentication prerequisites.
  </Accordion>
  <Accordion title="What is the GSTR-3B filing workflow using the API?">
    The GSTR-3B filing workflow follows eight steps: fetch existing return data, auto-calculate liability for validation, save the return JSON to the portal, poll return status until save completes, offset liability using ITC and cash, poll status again until offset completes, generate EVC OTP for the authorized signatory, and file the return with OTP verification.
  </Accordion>
  <Accordion title="Why do I need to poll GST return status after save and offset?">
    The GST portal processes save and offset requests asynchronously. Polling the [GST Return Status](/api-reference/gst/compliance/endpoints/taxpayer/common/gst_return_status) endpoint lets you confirm processing completion and catch validation errors before you proceed to the next step.
  </Accordion>
  <Accordion title="What is EVC OTP and why is it required for filing?">
    EVC (Electronic Verification Code) OTP is a one-time password sent to the authorized signatory's registered mobile number or email. EVC OTP authenticates the signatory before filing GSTR-3B. Generate the OTP using the [Generate EVC OTP](/api-reference/gst/compliance/endpoints/taxpayer/authentication/generate_evc_otp) endpoint with the signatory's PAN.
  </Accordion>
  <Accordion title="What is the difference between GSTR-3B and nil GSTR-3B?">
    Regular GSTR-3B is filed when a taxpayer has transactions, tax liability, or ITC to claim for the period. Nil GSTR-3B is filed when there are no outward or inward supplies, no liability, and no ITC to claim. Nil filing is still mandatory to maintain compliance. Use the [File Nil GSTR-3B](/recipes/gst/gstr-3b/file_nil_gstr_3b) recipe for nil returns.
  </Accordion>
  <Accordion title="What is liability offset in GSTR-3B?">
    Liability offset is the process of allocating Input Tax Credit (ITC) and cash ledger balance to pay tax liability. The [Offset Liability](/api-reference/gst/compliance/endpoints/taxpayer/gstr-3b/offset_liability) endpoint allows you to specify how much ITC and cash to use for each tax head (IGST, CGST, SGST, cess). Offset must complete before filing.
  </Accordion>
  <Accordion title="What prerequisites are required before filing GSTR-3B?">
    Before filing GSTR-3B, ensure GSTR-1 is filed for the same return period, you have sufficient balance in cash or ITC ledger for liability offset, and your taxpayer access token is valid (6-hour validity). Create a taxpayer session using the [Generate Taxpayer Session](/recipes/gst/authentication/generate_tax_payer_session) recipe.
  </Accordion>
  <Accordion title="How do I handle errors during GSTR-3B filing?">
    Check [GST Return Status](/api-reference/gst/compliance/endpoints/taxpayer/common/gst_return_status) for validation errors after save or offset operations. Fix any data issues and re-save before proceeding. For API-level errors, refer to the [Errors guide](/guides/developer-resources/errors) for HTTP status codes and resolution steps.
  </Accordion>
</AccordionGroup>
