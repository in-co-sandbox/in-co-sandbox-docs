Bulk PAN verification accepts a JSON file in [Sheet JSON format](/guides/developer-resources/sheet_json). The `payee_workbook` contains one `payee_sheet` with one `payee_table`.

## Input requirements

The table header is `["sr_no", "pan"]`. Each row contains these values in the same order.

| Column | Type | Description |
|:-------|:-----|:------------|
| `sr_no` | Integer | A positive serial number identifying the input row. |
| `pan` | String | The PAN text to submit to TRACES. |

The JSON file must be at most **5,000,000 bytes**. Sandbox checks the file size during processing after upload.

Sandbox submits PAN strings unchanged. For repeated exact PAN strings, verification keeps the first row and its `sr_no`, and ignores later rows.

## Upload the workbook

After you [create a job](/api-reference/tds/compliance/pan-verification/endpoints/submit_job), upload the JSON file to `data.json_url` with HTTP PUT and `Content-Type: application/json`.

```bash
curl --request PUT \
	--url '{json_url}' \
	--header 'Content-Type: application/json' \
	--data-binary '@payee_workbook.json'
```

The signed upload URL authorizes this request. Omit the Sandbox `Authorization` and `x-api-key` headers when uploading the file.

Signed upload and download URLs are valid for 24 hours. Uploaded and generated files are retained for 30 days.

After uploading, [poll the job](/api-reference/tds/compliance/pan-verification/endpoints/poll_job) for the result. See [Verify PANs in bulk](/recipes/tds/pan-verification/verify-pans-in-bulk) for the complete workflow.
