## Overview

Some APIs require you to upload an input payload (JSON, ZIP, CSV, etc.).  
Instead of sending large bodies directly to Sandbox APIs, you upload the payload to a secure **pre-signed AWS S3 URL** using a `PUT` request.

The system then processes your payload asynchronously as a **job**.

---

## When a PUT Request Is Required

You will see this workflow whenever the API endpoint mentions steps like:

1. **Submit Job** → returns `id` (job ID) + `url` (signed S3 upload URL)  
2. **PUT Payload** → upload your file or JSON payload to the S3 `url`  
3. **Poll Job** → retrieve the processed output  

If an API reference page contains a **PUT Request** section, it uses this flow.

---

## How PUT Requests Work

### Step 1 — Submit the Job

You first call the API endpoint that initializes the job.  
The response includes:

- `id` — Job ID  
- `url` — pre-signed S3 PUT URL  
- `entity` — internal identifier  
- `status` — current state (usually `created`)  
- timestamps (`created_at`, `updated_at`)


```json title="Sample Submit Job Response"
{
  "code": 200,
  "timestamp": 1765271144915,
  "data": {
    "id": "84f3844d-75ad-40a9-ab8d-73a7a4da7db2",
    "created_at": 1765271146287,
    "updated_at": 1765271146287,
    "@entity": "in.co.sandbox.it.calculator.pnl.crypto.job",
    "url": "https://in-co-sandbox-it-calculator-pnl-crypto-dev.s3.ap-south-1.amazonaws.com/84f3844d-75ad-40a9-ab8d-73a7a4da7db2/workbook.input?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Content-Sha256=UNSIGNED-PAYLOAD&X-Amz-Credential=AKTARBAE40KMVKC2ZT7X%2F20251209%2Fap-south-1%2Fs3%2Faws4_request&X-Amz-Date=20251209T095046Z&X-Amz-Expires=864000&X-Amz-Signature=6da109e7381eadb238fe7452cc06b97322567af8952bcd07def14759681f3b74&X-Amz-SignedHeaders=host&x-amz-checksum-crc32=AAAAAA%3D%3D&x-amz-sdk-checksum-algorithm=CRC32&x-id=PutObject",

```
### Step 2 — PUT the Input Payload

Once you receive the pre-signed S3 URL, upload your payload (JSON, ZIP, CSV, etc.) directly to that URL using an HTTP `PUT` request.

The `url` returned in Step 1 is an **AWS S3 pre-signed URL**, not a Sandbox API endpoint.

This means:

- **Do NOT send your Sandbox API key** in the PUT request  
- **Do NOT modify the URL** (not even a trailing slash)  

#### Requirements

- **Method:** `PUT`  
- **Headers:** only `Content-Type` (and occasionally checksums if required)  
- **Body:** your input payload  
- **No Authorization headers**  
- **No Sandbox-specific headers**


```bash title="cURL Example"
curl -X PUT \
  -H "Content-Type: application/json" \
  --data '@payload.json' \
  "https://in-co-sandbox-it-calculator-pnl-crypto-dev.s3.ap-south-1.amazonaws.com/84f3844d...&x-id=PutObject"
```
## Step 3 — Poll the Job Status

After successfully uploading your payload to the pre-signed S3 URL, the job begins processing on Sandbox servers.  
Use the **same endpoint from Step 1**, but switch to a `GET` request with the `job_id` returned earlier.

Jobs usually finish within a few seconds, but large payloads or complex calculations may take longer.  
Implement retry logic with **exponential backoff**.

### Job Status States

A job can be in one of the following states:

- **created** — job created, awaiting processing  
- **in_progress** — Sandbox is reading your payload and computing results  
- **success** — output is ready to consume  
- **error** — processing failed; inspect the returned error message  

### Polling With Job ID

Use **the same route as Step 1**, only changing the method to `GET` and adding `job_id`.
```bash
curl -X GET \
  "https://api.sandbox.co.in/<workload>/<function>/<sub_function>?job_id=<job_id>" \
  -H "x-api-key: <your_api_key>"
```
